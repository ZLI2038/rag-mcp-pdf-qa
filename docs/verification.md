# 修复与验证

## 修复范围

- 语音提交以一次实际识别周期为单位去重；界面重渲染不会重发，相同问题在下一轮仍可再次提交。
- 请求进行中阻止重复提交；关闭语音模式后不会因旧的模型响应或播报结束回调重新打开麦克风；组件卸载会取消前端 HTTP 请求。
- 上传接口验证扩展名、媒体类型、PDF 文件头和真实可解析性；拒绝空上传、非 PDF、损坏文件、无文字 PDF 和超限文件。
- 删除全局“当前文件路径”，使用会话标识与随机文档编号查找文件。错误会话不能读取或删除文件，同名上传也不覆盖旧文档。
- PDF 只在上传时解析、分块；首次提问建立索引，后续和并发问题复用索引。构建失败会清除失败状态以便重试。
- MCP query 去空白后长度为 1–2000，num 为 1–10 的整数；限制实际返回的搜索条数。
- 并发首次 MCP 调用共用完整的连接过程；连接失败后可重连。错误响应不暴露上游细节。
- 前端上传和问答共用同一个可配置后端地址；支持删除当前 PDF。
- 文档只存内存，有闲置过期、会话数量和进程总数量上限。

## 复现

在项目根目录执行：

```sh
npm run test:ci
npm run test:server
CI=true npm run build
```

仅当允许使用现有密钥进行少量真实调用时执行：

```sh
ALLOW_LIVE_API_TESTS=1 npm run test:live --prefix server
```

Node 后端测试使用系统分配的本机临时端口，不依赖固定的 5001 端口、个人文件或磁盘上传目录。运行环境必须允许本机监听端口。

## 验证边界

- 自动化语音测试覆盖识别事件和播放回调，但不验证真实麦克风输入、识别准确率或特定浏览器的权限提示；仍需用真实浏览器进行一次人工语音验收。
- 内存存储与随机会话标识适用于本地演示。账户认证、公网限流、跨实例存储及部署运维不在本次修复范围内。
- 取消浏览器请求不保证已经开始的外部 API 调用停止计费。
- 存量 React Testing Library 依赖仍会输出 act 弃用提示，未影响当前测试结果。
- GitHub Actions 配置已加入，但云端运行结果要在仓库上传后确认。工作流用法参考 [actions/checkout](https://github.com/actions/checkout) 和 [actions/setup-node](https://github.com/actions/setup-node) 的官方说明。
